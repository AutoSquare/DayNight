# 修复：手动更换主题后被立刻切回（晨昏线 1.1.3）

## Context

在主题库点卡片换主题后，1 秒内弹出「即将切换主题」倒计时，随后被切回计划主题。日志 `20261125.log` 有完整记录：02:42:29 手动应用「日间主题」→ 02:42:30 弹提示 → 02:42:36 切回「发光」。

根因：主题库的应用路径（`DayNight/ViewModels/MainViewModel.cs:167` 的 `ApplyThemeDirect`）只换主题，不向调度引擎登记手动状态；而每秒一次的调度检查（`DayNight/Services/ScheduleEngine.cs:131-140`）把「实际主题 ≠ 当前时段计划主题」一律当作跑偏去纠正。规则页点行和托盘手动切换因为登记了手动状态，所以不会被切回。在 Windows「个性化」里换主题走的是同一条纠正规则，同样会被切回。

## 已确认的决策

| 待定项 | 结论 |
|---|---|
| 主题库换的主题 | 保持到下一个切换点，到点交还给计划 |
| 「个性化」里换主题 | 本次一并修：同样保持到下一个切换点 |
| 区分“用户手动”与“需要补切” | 程序运行中检测到主题变化 = 用户手动 → 登记，下一次自动切换时清除；没有登记 = 需要补切 → 直接切 |
| 交付 | 版本升 1.1.3，暂不打包；用 computer-use 真机验证，直到确认为止 |

## 实现

**1. 数据模型 `DayNight/Models/ManualState.cs`**
- 新增 `IsTemporary`（临时保持标记），类注释补充第三种模式：只覆盖当前时段，到下一个切换点恢复计划。旧配置没有该字段，默认 false，保持原语义。

**2. 调度引擎 `DayNight/Services/ScheduleEngine.cs`**
- 新增 `HoldUntilNextSwitch()`：登记临时保持，`HoldUntil` = 当前时段结束时刻（即下一个切换点），写日志「手动更换主题，保持至 …」。
- 新增 `NoteExternalChange(previousTheme, actualTheme, sinceLastCheck)`，返回是否登记。以下情况不登记，仍按补切处理：
  - 上一次读数为空（刚启动、读不到主题）
  - 两次检查间隔超过 `MaxWatchGap`（3 秒，说明中间睡眠或休眠过）
  - 主题没变，或变成的正是计划目标
  - 已有未到期的保持（继续沿用）
  - 处于“提前生效”状态时，替换为临时保持
- 新增 `GetEffectiveThemeId()`（当前应生效的主题），`Decide` 改用同一个定义。
- `GetSegmentViews`：临时保持按“无手动状态”推导四态，其余时段照常显示已结束/未来，当前标记跟随实际主题。
- `ClickSegment`：不沿用临时保持的到期时刻（规则页点行视为全新的手动选择）。
- `Decide` 里“保持中不动作、到期清除”的逻辑不改。

**3. 主题库路径 `DayNight/ViewModels/MainViewModel.cs`**
- 新增 `ApplyLibraryTheme(path)`：应用成功后，若主题不等于调度目标，则 `HoldUntilNextSwitch()` → `Save()` → `RaiseStateChanged()`；与目标相同则不登记。`ThemeLibraryPageViewModel.ApplyThemeNow` 改为调用它。结构与现有的 `ManualSwitchSegment` 一致。

**4. 每秒检查 `DayNight/App.axaml.cs`**
- 新增字段 `_lastTickAt` 记录上次检查时刻。
- `Tick` 在“正在应用主题”的提前返回之后、暂停判断之前调用 `NoteExternalChange`，登记成功则保存并广播状态。
- 启动后的第一次检查与间隔过长时不登记，所以开机、唤醒仍走原来的 `AlignNow` 直接对齐。**`AlignNow` 本身不改**，这是你要保住的开机自动切换。

**5. 界面文案**
- `Views/ThemeLibraryPageView.axaml.cs`：确认卡备注改为「…；不改动时段规则，保持到当前时段结束，之后按计划自动切换。」，帮助文案同步。
- `ViewModels/RulesPageViewModel.cs` 的 `DescribeSwitch`：临时保持不参与「保持该主题至 …」的提示。
- `Views/TimeAxisPageView.axaml.cs` 帮助：说明手动保持也来自个性化设置里的更换。

**6. 单元测试** 新建 `tests/DayNight.Tests/ManualThemeChangeTests.cs`（xUnit，沿用现有的可注入时钟写法）
- 临时保持在到期前不动作，到期后切往下一段且手动状态清空。
- 临时保持下其余时段四态保持自然标记，不出现「下一日」。
- 规则页点行会替换临时保持，不沿用其到期时刻。
- 外部变化登记；启动无读数、间隔过长、变成计划主题、已有保持时不登记；提前生效状态被替换。
- 临时保持经 JSON 往返后仍保留；不含 `IsTemporary` 的旧配置按原语义读取。

## 已知边界（按你定的原则推出，本次不扩大）
- 晨昏线没运行时换的主题，下次启动仍会对齐回计划。
- 程序运行期间，其他软件改了主题，会和手动更换同样对待，到下一个切换点恢复。
- 暂停调度期间换的主题会登记，恢复调度后保持到下一个切换点。
