## 2. 项目结构（在现有 `DayNight\` 单项目上分层）

```
DayNight/
├─ Models/            数据模型
│   ├─ ThemeSegment.cs        { StartTime TimeOnly, ThemeId string }
│   ├─ ScheduleConfig.cs      { Segments: List<ThemeSegment> }  （强制全天覆盖）
│   ├─ AppSettings.cs         外观主题/自启/静默/全屏延迟/OSD 开关与时长/通知开关/唤醒对齐
│   └─ ManualState.cs         { HoldSegmentIndex, HoldUntilDate }  手动保持状态（持久化）
├─ Services/
│   ├─ ThemeCatalogService.cs 枚举/解析 .theme、提取壁纸预览、读当前主题
│   ├─ ThemeApplyService.cs   整套主题应用编排与结果验证
│   ├─ ScheduleEngine.cs      调度核心（见 §4）
│   ├─ ManualOverrideService.cs 手动状态（当前/已结束/下一日/保持）计算与持久化
│   ├─ WindowsThemeManager.cs 原生主题管理器 COM 封装
│   ├─ FullscreenDetector.cs  SHQueryUserNotificationState 封装
│   ├─ AutostartService.cs    HKCU Run 键读写
│   ├─ ConfigStore.cs         config.json 读写（System.Text.Json）
│   └─ LogService.cs          滚动文件日志
├─ ViewModels/        MainViewModel + 四页 ViewModel（CommunityToolkit.Mvvm）
├─ Views/             MainWindow（NavigationView 外壳）+ 四页 UserControl + OsdWindow
├─ Assets/            daynight-logo.ico 等
└─ Program.cs / App.axaml
```

分层原则：调度与语义全部在 Services（可单测），ViewModel 只做绑定与转发；Windows 专属 P/Invoke 集中在 Services 内部。

## 3. 数据模型要点

### 3.1 日程（ScheduleConfig）
- 段列表按 `StartTime` 严格递增；所有起点精确到整分钟；段 i 覆盖 `[start_i, start_{i+1})`；末段跨日覆盖到首个起点
- `ScheduleDraft` 深复制有效计划，编辑在副本上调用 `ScheduleConfig.TryAddSegment/TryRemoveSegment/TrySetStartTime`；添加只拆分末段，删除起点保留其他时间，表盘编辑后按起点重新排序并保留主题绑定。`MoveBoundary` 将全天比例吸附至五分钟，窄区间以合法分钟约束兜底。
- 规则页以 `IsEditing` 控制草稿入口。浏览态展示已保存时段和调度状态；编辑态显示表盘、主题选择及分界线手柄，每一行均可打开表盘，包括第一行。保存失败保留编辑态，取消编辑还原有效计划。
- “时段规则”页标题右侧放置编辑入口，进入编辑后原位显示取消和保存。页面按钮采用 34 DIP 高度，内容水平、垂直居中。上方“全天分布”展示 6 小时间隔的刻度，并提供自动切换和复位操作。下方“切换计划”按开始时间、主题、结束时间排列，编辑时可添加或删除时段。浏览时点击主题区域沿用切换确认流程。
- `AppContext.TrySaveSchedule` 先原子落盘独立快照，成功后才替换有效段列表、清除旧保持并通知调度；失败保留原日程和草稿。`ConfigStore.Save` 使用同目录独立临时文件加替换，返回实际保存结果。
- 真正的调度段尾使用 `GetSegmentEndDateTime`，以该次时段开始的日期为基准，末段返回次日首个起点。规则分布条与今日时间轴共用 `GetDaySlices`，将跨午夜的时段按当天可见范围绘制。

### 3.2 手动状态（ManualState，持久化到 config.json）
- 无手动状态时，按当前时刻计算计划目标；界面的「当前」取自 Windows 实际主题。
- 手动切换（任意行）→ 记录 `{SegmentIndex, HoldUntil: TimeOnly}`：
  - 调度引擎手动应用已结束/下一日时段：`HoldUntil = 该段段尾`（跳过今天剩余 + 跨午夜日程切换，到明天段尾恢复）
  - 调度引擎手动应用当前/正常时段：不进入保持，仅对齐主题（无持久状态，或记为一次性覆盖）
- 幂等：已处于保持态再点灰行 → 仅换 `SegmentIndex`
- 复位：清空 ManualState → 按当前时刻对齐；遵守自动开关。只有保存新计划才取消旧保持，草稿编辑不影响运行状态。

### 3.3 四态标记推导（渲染层的唯一事实）
`ScheduleEngine.GetSegmentViews` 按 Windows 当前主题的规范化路径匹配规则，供规则页和时间轴共用。相同主题安排多次时，优先选匹配的手动段，否则从当前时段往前找最近一次匹配，跨午夜继续查找。计划外主题或系统读数为空时，全部行都不显示「当前」。已结束、下一日和下次切换时间仍由计划与手动状态计算。

## 4. 调度引擎（ScheduleEngine）

- 常驻 UI `DispatcherTimer`（1s）+ 事件驱动（Resume、保存计划、手动操作）。`AppContext.ScheduleChanged` 取消旧 OSD、清空跳过记录并立即对齐。`GetUpcomingSwitch` 纯查询提前窗口内的下一次变化，不提前清理手动状态。
- 每次tick判定：
  1. 读取 Windows 当前主题，更新界面；暂停时仅观察
  2. 全屏检测命中 → 延迟，关闭待执行 OSD，每秒重新检查
  3. `ManualState` 保持中且 `now < HoldUntil 今日折算` → 不动作；越过 HoldUntil → 清除手动、对齐
  4. 无保持：当前段主题 ≠ 已应用主题 → 触发切换流程（先 OSD 倒计时，结束后应用）
- 切换流程：弹 OSD（N 秒倒计时）→ 原生应用整套 `.theme` → 核对系统结果 → 成功通知 / 失败提示 → 写日志
- 成功通知从已应用的主题文件读取与主题库一致的显示名，并解析 Windows 的本地化资源。例如中文系统中的 `themeA.theme` 显示为「发光」。若文件已无法读取，通知显示「主题已切换」。
- 正常切换的 OSD 持有绝对截止时间，50ms 更新显示，截止后再核对当前决策；到点不额外等待 N 秒。全屏退出等错过切换点的补切保留完整提示时长。
- OSD 期间允许托盘"跳过本次"；使用日期与段起点标识本次执行，次日不沿用跳过状态。
- OSD 尚未完成或主题正在应用时不再次入队；主题应用使用 `AppContext.IsApplyingTheme` 统一互斥。倒计时结束、启动、唤醒及复位对齐时重新读取 Windows 当前主题。应用返回后也重新读取，包括仅部分外观生效的情况。失败主题间隔 30 秒重试；期间若进入另一个主题的时段，该时段照常执行。
- 唤醒/启动对齐：直接应用当前段主题，无 OSD

## 5. Windows 集成要点

### 5.1 主题枚举与预览
- 目录：`%LOCALAPPDATA%\Microsoft\Windows\Themes\**\*.theme`、`C:\Windows\Resources\Themes\**\*.theme`
- `.theme` 为 UTF-16 LE INI：读 `[Control Panel\Desktop]` 的 `Wallpaper=`；壁纸图缩放生成预览；无壁纸时用占位图
- 当前主题：`HKCU\...\Themes\CurrentTheme`（值为 .theme 全路径，做匹配）

### 5.2 应用整套主题

旧实现手动设置壁纸、光标和图标，未处理系统明暗、应用明暗、强调色、声音与幻灯片，还主动写入 `CurrentTheme`，因此不符合整套主题需求；该实现已移除。

当前通过 `WindowsThemeManager` 封装 Windows 原生 `IThemeManager2`：
- 在专用 STA 线程创建、初始化、使用并释放 COM 对象。
- 使用 `AddAndSelectTheme` 按完整路径应用，应用标志为 0，不跳过任何主题组成部分；包标志为 4，请求静默应用。
- 主题实际解析、壁纸/幻灯片、系统与应用配色、强调色、声音、光标和图标的处理交给 Windows；不再逐项模拟，也不再主动改写 `CurrentTheme`。
- `ThemeApplyService` 将应用串行化，核对 Windows 更新后的当前主题路径、主题明确声明的两种明暗模式及固定强调色。对异步状态刷新最多等待五秒；自动取色不与预定义颜色做固定值比较。
- COM 失败或状态不符返回失败并记录日志，界面提示失败；不会用仅切换壁纸或仅改注册表的方式冒充成功。
- 主题应用仍由后台任务调用。规则页的手动保持状态在实际应用成功后保存；处理中显示“正在应用整套主题…”，避免提前标记成功。
- `IThemeManager2` 是非公开 Windows 接口；已在本机 Windows 11 26320 上验证，其他系统版本仍需兼容性测试。若接口不可用，明确报错，不静默降低功能。

`--apply <path>` 与 `--smoke` 均走该链路；`--smoke` 依次验证内置浅色、深色主题，然后恢复运行前的主题。它会实际切换桌面，不能作为无副作用的普通单元测试。

### 5.3 OSD 窗口
- 提示卡宽 400 DIP，内容按 14 DIP 圆角裁剪。顶层边框使用内外两个同半径圆角矩形的差集。内框向内缩进 1 DIP，直边宽 1 DIP，圆弧在 45° 方向宽约 1.4 DIP，以补偿斜向像素抗锯齿造成的视觉减薄。日夜使用各自的边框色，外弧以外保持透明。
- 外观设置为「跟随系统」时，倒计时预览采用即将切入主题的应用明暗模式，依次回退至该主题的系统模式和当前应用外观。用户明确选择浅色或深色时，提示卡遵循该偏好。壁纸预览保留原图颜色，正文、边线和进度条使用相应主题资源。
- `Win32`：`SetWindowLongW(GWL_EXSTYLE, ...| WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW)` 实现点击穿透
- 定位：主屏工作区横向居中、纵向约 44%，DIP 尺寸按屏幕缩放换算物理坐标。初始高度 266 DIP，保留内容自适应；`SizeChanged` 在内容完成测量后重新定位，避免使用打开瞬间的系统默认高度导致偏移。倒计时结束自关并回调引擎，提前关闭停止计时且不回调应用。

### 5.4 全屏检测（双层判定）
1. `SHQueryUserNotificationState`：独占全屏 `QUNS_RUNNING_D3D_FULL_SCREEN` / 演示模式 `QUNS_PRESENTATION_MODE` 直接延迟。`QUNS_BUSY` 不单独作为全屏证据；本机普通桌面持续返回 BUSY 且前台未铺满，旧版因此无法自动切换。
2. **前台窗口铺满所在显示器兜底**（`GetForegroundWindow` + `GetWindowRect` vs `MonitorFromWindow`+`GetMonitorInfo`，容差 2px，排除 Progman/WorkerW/Shell_TrayWnd）
   —— 实测 PowerPoint 展台放映/浏览器视频全屏时 QUNS 仍返回 `QUNS_ACCEPTS_NOTIFICATIONS`，仅靠 QUNS 会漏判，故必须双保险。
   启动/唤醒的对齐（AlignNow）同样受全屏延迟约束，退出全屏后由下一轮 tick 补切。

   参考：[Microsoft 通知状态定义](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ne-shellapi-query_user_notification_state)、[PowerToys 对覆盖层导致持续 BUSY 的记录](https://github.com/microsoft/PowerToys/issues/45548)。日志仅在全屏判定变化时记录；界面显示“全屏中，切换已延迟”。

### 5.5 自启
- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 键名 `DayNight`，值 `"exe路径" --silent`

## 6. 界面实现要点

- **导航（2026-11-18 重构）**：侧栏为独立 `ListBox`，`SelectedIndex` 双向绑定 `MainViewModel.CurrentPageIndex`（禁止 Button+CommandParameter 字符串转 int——MVVM Toolkit RelayCommand 强转会静默失败导致"点不动"）
- **页面容器**：`ContentControl Content="{Binding CurrentPage}"` + App 级 `ViewLocator` 数据模板，当前页 VM 按类型解析对应 View；禁止多页 Grid 叠加 IsVisible 显隐
- **强调色**：App 顶层 Resources 覆盖 `SystemAccentColor` 系列为 Logo 藏青（放 ThemeDictionaries 内无效，Fluent 运行时从顶层读取）
- 主题库与时段规则共用主窗口内的切换确认卡。卡片宽 370 DIP，在主窗口居中，底部操作栏用分隔线区分。显示时背景变暗并轻度模糊，焦点移到“取消”。按 Esc、点击遮罩或“取消”关闭卡片，只有确认才执行应用主题的回调。帮助与未保存计划提示继续使用 Dialogs.cs 中的独立窗口。
- **性能红线**：主题扫描与 Apply（含壁纸转码）必须后台线程，UI 线程调用会"未响应"
- Debug 构建提供 `--page N`、`--uitest`、`--smoke` 自测入口。Release 排除界面自测、冒烟工具和开发者工具依赖。正式命令行保留 `--silent` 与 `--apply <path>`。

## 9. 2026-11-18 主题库、设置记忆与原型还原修复

### 9.1 主题元数据
- `ThemeCatalogService` 按 INI 节和完整键名读取数据，只使用 `[Theme]` 的名称和 `[Control Panel\Desktop]` 的壁纸，避免 `.A`、`.W` 兼容节覆盖主节。
- 主题读取支持带 BOM 的 UTF-16、UTF-8，以及无 BOM 的系统 ANSI 编码。`ThemeFileContent.Parse` 共用同一读取函数，保证中文壁纸在预览和应用阶段一致。
- `DisplayName=@module,-resourceId` 使用 Windows `SHLoadIndirectString` 读取本地化资源，不再将 `aero`、`themeA` 等文件名直接显示为系统主题名。
- 幻灯片统计现存 `ItemNPath` 文件并按路径去重；解析相对路径和环境变量；`WindowsSpotlight=1` 单独显示为 Windows 聚焦。只有确实声明 `[Slideshow]` 才显示幻灯片，缺失预览不再被误判为幻灯片。
- 扫描保留用户保存的主题、系统主题和注册表引用的当前主题；非当前的根目录 `Custom.theme` 是未保存快照，不列为另一套已安装主题。不按壁纸去重，以免丢失同壁纸、不同配色的主题。
- 扫描与缩略图解码在后台线程执行，完成后同时更新主题库、规则选择器和时间轴；显示名称、缩略图和当前标记复用同一份数据。
- Windows 的未保存主题、聚焦实时图片与 `.theme` 文件可能不同步；列表按可读取的主题文件呈现，不承诺与系统设置的临时状态逐像素一致。

### 9.2 自动切换开关
- 新增 `AppSettings.AutoSwitchEnabled`，旧配置缺少该字段时兼容默认开启。页面和托盘通过 `AppContext.SetAutoSwitchEnabled` 写入配置并广播状态。
- `AppContext` 在创建引擎时恢复暂停状态，早于调度计时器和启动对齐。
- 启动、唤醒、倒计时结束的自动应用均检查暂停。关闭开关同时关闭未完成的 OSD；恢复开关后按引擎决策立即对齐，仍遵守全屏延迟和手动保持。
- 托盘文案、规则页开关和时间轴保持同步；手动应用不受自动开关限制。

### 9.3 原型布局
- `MainWindow` 按原型采用 40 像素自绘标题区、196 像素导航区和底部状态区，保留窗口拖动、最大化、最小化、关闭和帮助。Avalonia 12 使用 `WindowDecorations=BorderOnly` 保留窗口边框。
- 全局中文字体指定为 Microsoft YaHei UI，页面标题为 22 像素，卡片内边距为 18×16 像素。开关移除英文 On/Off。
- 主题库使用自适应三列布局，卡片图片裁剪至圆角边界，名称过长显示省略号；亮暗色使用同一组动态资源。
- 时间轴当前主题卡和规则行使用真实壁纸缩略图；规则当前行高亮，卡片底部恢复按时段比例划分的小时间带；暂停时弱化计划色带。
- 外观三段选择按钮同步选中状态，避免界面已换色但按钮没有高亮。
